# Plan del producto piloto

Este bloque organiza el desarrollo incremental de un producto pequeño para validar la propuesta con **un solo rubro**. El objetivo es que el flujo funcione de punta a punta antes de replicar y adaptar la solución a otros rubros.

## Archivos

- [CONTEXTO_PROYECTO.md](./CONTEXTO_PROYECTO.md): contexto breve y decisiones ya tomadas. Leer al retomar el trabajo.
- [ROADMAP.md](./ROADMAP.md): actividades ordenadas, dependencias y criterios para avanzar.
- [DECISIONES_PENDIENTES.md](./DECISIONES_PENDIENTES.md): información que se relevará en el lugar y decisiones que no deben suponerse.
- [PREPARACION_ANTES_DESARROLLO.md](./PREPARACION_ANTES_DESARROLLO.md): checklist de información y decisiones necesarias antes de programar.
- [PRUEBAS_ACEPTACION.md](./PRUEBAS_ACEPTACION.md): casos mínimos para verificar el MVP antes de darlo por funcional.
- [REPOSITORIO_Y_DESPLIEGUE.md](../REPOSITORIO_Y_DESPLIEGUE.md): define qué se incluirá en GitHub y qué archivos deberán vivir dentro de esta carpeta para desplegar.

## Prioridad de este plan

Este plan define el alcance del **piloto de pasantía**. Los documentos previos de la Propuesta 1 describen una visión más amplia (varios rubros, altas y modificaciones, y una integración técnica planteada). No implementar esas funciones como parte del piloto hasta validarlas y agregarlas explícitamente al alcance.

El piloto no se desplegará ni se conectará a datos reales hasta que la interfaz y el flujo estén desarrollados y probados localmente. El modelo concreto de datos y la base de Firebase se definirán después de relevar el formulario y validar su estructura.

Este es el único proyecto activo del workspace. Las Propuestas 2 y 3 se conservan como antecedentes y quedan fuera de alcance. Para mantener en paralelo las entregas, seguir `.github/skills/seguimiento-pasantia-seminario/SKILL.md`: bitácora por sesión y actualización de la etapa de Seminario correspondiente.
